## P0-4 三层设计 · 逐层实测

直接对上游 `generateContent` 打三组对照请求：

| 请求形态 | 上游响应 |
|---|---|
| `functionCall` 不带 `thoughtSignature` | **400** `Function call is missing a thought_signature...` |
| `thoughtSignature: "skip_thought_signature_validator"`（字面量） | **200** ✅ |
| `thoughtSignature: "c2tpcF90aG91Z2h0X3NpZ25hdHVyZV92YWxpZGF0b3I="`（SDK 实际发出的 base64 形态） | **200** ✅ |

**结论：此前担心的"哨兵被 SDK base64 编码后不被上游识别"不成立——两种形态上游都接受。P0-4 第三层降级有效。**

代理端全链路验证：

- **第一层（短 id + 缓存）**：round-1 返回 id `y0dyoBaB`（8 字符，无 `__thought__`）→ round-2 携带工具结果 → **200，无哨兵警告**（缓存命中）。
- **第二层（内嵌兼容）**：打开 `embed_thought_signature_in_id` 后 id 长 367 字符、含 `__thought__`，可正常解析回传。
- **第三层（哨兵降级）**：**重启服务清空缓存**后重发 round-2 → **200 成功**，日志出现预期的
  `⚠️ [工具调用] 未能恢复思考签名…已使用官方跳过校验哨兵`。

## 追加改动 · 2026-07-26（控制台开关精简 + 预填充改进）

### 移除「思考签名内嵌 tool_call_id」开关

该开关原本只为多副本部署（多进程/多容器共享负载）准备：签名存在进程内存里，
请求落到另一个副本就取不回。但实机验证已确认**第三层哨兵降级有效**——取不回签名时
请求仍返回 200，只是模型表现略降。而默认 Dockerfile 是**单 worker**，普通用户不可能触发。

因此移除开关本身，只保留对旧 `__thought__` 格式的**解析**（升级前发出的 id 可能还在
客户端历史里）。不再生成该格式。

### 预填充默认模式改为 `keep_turn`

**动机**：预填充在本项目的主要用途，是用酒馆预设自带的思维链顶掉模型原生思维链，
以获得更好的写作效果。此时预填充往往是 `<thinking>` 这类**未闭合的开头**。

原 `smart` 模式在 3.x 上会把预填充**塞进 user 消息**，模型于是把自己写了一半的内容
当成"用户贴来的参考文本"。`keep_turn` 则保留它作为 model 轮次，只在其后补一句极短的
user 推动语——3.x 拒绝的是"以 model 轮次**结尾**"，并不禁止它出现在中间。

**实机对照**（`gemini-3.6-flash`，system 要求先输出 `<thinking>` 三条要点再写正文，
预填充 `"<thinking>\n1."`，用户要求写"主角推开了地下室的门"，各 3 次）：

| 模式 | 切题 | 预设格式 | 实际输出片段 |
|---|---|---|---|
| `smart`（旧默认） | **0/3** | **全部丢失** | `米的柱状容器。绿色的荧光液体` / `靴底踩在格栅` / `《09号体征观察与基因重塑` |
| `keep_turn`（新默认） | **3/3** | 完整 | `<thinking>\n1. 主角迈入地下室，发现空气中弥漫着旧报纸和高浓度防腐剂的怪味。...` |

smart 不仅跑题，连预设要求的 `<thinking>` 结构都没有生成——模型从 `1.` 直接往下编。
另在普通续写场景（非思维链）各测 9 次，两者的"重复预填充/添加前言"缺陷率均为 0，
即 keep_turn 在已测场景中**不劣于** smart。

完整代理链路复验：预填充正确拼回输出开头，内容切题，格式完整。
`smart` 保留为可选项（控制台标注"旧行为"）；2.5 系仍走原生透传，不受影响。

### 生图 system 指令开关的实测影响

同一提示词（system=「纯黑白线稿风格，只有线条，不要颜色和阴影」，user=「画一只猫」）：

- **开关关**（原版行为）：输出**彩色写实照片**——木地板上的虎斑猫，system 被完全丢弃。
- **开关开**：输出**黑白线稿**——纸上钢笔画风格的猫，完全符合 system 要求。

结论：这个开关对生图**影响巨大**，原版无条件丢弃 system 是实打实的功能缺失。
默认仍保持关闭以免改变既有行为，但建议用生图的用户打开。
