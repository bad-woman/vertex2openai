### 唯一需要真机才能定论的遗留项

**D-4：`FunctionResponse` 到底该传 `id` 还是 `call_id`。**

官方迁移清单要求走 `generateContent` 时所有 `FunctionResponse` 都带 `call_id` 和 `name`，而代码传的是 `id=`。在装了 SDK 的环境里跑一行即可定论：

```bash
python -c "from google.genai import types; print(types.FunctionResponse.model_fields.keys())"
```

- 若输出里有独立的 `call_id` 字段 → 需要同时设置或改用它
- 若只有 `id`（序列化为 `callId`）→ 现有代码正确，在 `message_processing.py` 的 `func_resp_kwargs` 处加注释锁死结论

## 四、实施过程中发现的两个"计划外"问题

这两个不在原整改方案里，是动手改的时候撞出来的，都已修复：

1. **文本保真**：`_extract_markdown_images_to_parts()` 无条件执行 `re.sub(r"[ \t]+", " ", ...)`，导致**所有**纯文本消息的缩进和多空格被静默压平——代码块、ASCII 图、酒馆预设排版全部受影响。这是原版 Express 通道一直存在的问题。已改为仅在确实抽走内联图片时才压平。

2. **掩码回填陷阱**：把 `/api/settings/runtime` 改成返回 Cookie 掩码之后，控制台原本会把返回值回填进输入框，保存时会把真实 Cookie 覆盖成掩码字符串。已改为掩码只作 placeholder 展示，输入框留空表示"保持原 Cookie 不变"，后端同步支持只更新 Project ID。

## 五、为实机验证专门加的可观测性

原版 Express 通道不打印出站参数，思考档位是否真的生效**没法直接观察**。因此新增了一个控制台开关：

> **模型参数 → 出站参数调试日志**（`debug_outbound`，默认关）

打开后两条通道都会在运行日志里打印实际发出的 `thinkingConfig` 与采样参数，例如：

```
🔎 [出站调试] Express 通道 模型=gemini-3.1-pro-preview thinkingConfig={'include_thoughts': True, 'thinking_level': 'low'}
🔎 [出站调试] Express 通道 生成参数={'thinking_config': {...}, 'max_output_tokens': 4096}
```

**验证 P0-1 / P0-2 / P1-7 时请务必先打开这个开关。** 旧的 `cookie_debug` 保留为 Cookie 通道的额外诊断开关，两者独立。

## 六、部署与回滚

### 启动

```bash
# Docker（推荐，已配好数据卷）
docker compose up -d          # 注意先改 docker-compose.yml 里的 API_KEY

# 本地
cd app && uvicorn main:app --host 0.0.0.0 --port 7860
```

需要 **Python 3.11+**（代码用了 `str | None` 语法）。

### 两个新环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `STATE_DIR` | `.` | `web_state.json` 的存放目录。Docker 下请指向挂载卷，否则重建容器丢全部设置与 Cookie |
| `ALLOW_DEFAULT_KEY` | 空 | 仅用于在公开托管环境临时放行默认 `API_KEY`，正常部署不要设 |

### 行为变更提示（升级时注意）

- `retry_max` 语义变了：现在明确是"重试次数"，总请求数 = `retry_max + 1`。原版 Express 通道当成总次数，设 0 时一次请求都不发。
- 控制台 Cookie 输入框现在**留空表示保持不变**，不再回显完整 Cookie。
- Cookie 通道现在会**拒绝**带函数调用的请求（返回 400），而不是静默发出错乱历史。
- 默认口令仍为 `123456` 时会打红色告警；若同时检测到公开托管环境（HF Space 等）会**拒绝启动**。

### 回滚

改动按 PR-1～PR-4 分组，每组独立可回滚（见 01 号文档第 8 节）。若只想回退某一项，`04-full.diff` 里按文件和 ID 注释定位后反向 apply 即可——每处改动的代码注释里都写了对应的问题 ID（如 `# P0-1：...`）。
